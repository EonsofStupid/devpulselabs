# POA&M — the preset system, and the Library it feeds

**Spec:** `docs/design/design-system.md` — §2b semantic treatments (NEW,
ratified 2026-07-27), §1 elements, §7 build order steps 2–3.
**Reference implementation:** `PORT/devpulse labs/` — RenderForge and its
generated availability manifest.
**Sibling program:** `docs-history-2026-10-12:docs/plans/poam-visual-experience.md` (V1–V5). Its MOCK
GATE governs *styling* passes; P1/P2 here change no pixels and are not gated.

## Objective

Two vocabularies, deliberately separated, which this program keeps separate:

- **What the operator sees.** Clicking **Library** shows **Templates → Blocks →
  Elements**, greatly expanded, well organized. Those three words, and the
  plain-language shelf names beneath them, are the only vocabulary that ever
  reaches the screen.
- **What the code models.** **Presets** — the platform/industry model (Style
  Dictionary's core→semantic split, CVA/Panda "recipes"): one complete look per
  KIND of thing, every axis, with per-state groups, authored as data and
  generated into a manifest.

And one flow, which is the product:

> **new or existing card → click → overlay appears → select → preview → save**

Selecting means reaching the Templates→Blocks→Elements ladder **from inside the
overlay**, applying it to the open card, seeing it in the live pane, and having
it already saved.

## Where this actually stands (ground-truthed in-session, `53b321f`)

**The preset layer does not exist.** `crates/coldlight/tokens/presets.json` has
exactly two groups:

```
look:   5     (whole-slide looks — "Neon intro", "Glacier stat", …)
motion: 3
```

Eight entries, and neither group is a preset for a *kind of element*. There is
no per-element-kind preset, no per-state group, no manifest. For scale, the
PORT's generated manifest reads:

```
presets: 537 · hues: 53 · traits: 3 · composition: 2 · states: 4
"GENERATED by RenderForge — the availability contract the editor reads."
```

That last clause is the law worth porting: the editor can only offer a look
that provably exists. Without it a Library "expanded greatly" is a wall of
guesses.

**The composite layer DOES exist and is good.** `traits.json` carries
neubrutalist · claymorphic · cyber · retro; `compose(tone, base, &stack, state)`
resolves them; `HUE_COUNT` is 53, `EFFECT_COUNT` 18, `MOOD_COUNT` 10,
`ICON_COUNT` 24. §2a is built. §2b — the semantic binding *over* it — is not.

**Almost nothing consumes it.** Four files in 68 crates call `compose()`:
`author.rs`, `controls.rs`, `library.rs`, `viziwiz/palette.rs`. Every other
surface reaches past the system into raw tokens and hand-assembles, which is
why a census of pressable things found six competing implementations
(`shell::icon_button`, `editor::chip`, `editor::big_button`,
`library::chip_row`, `composer::chip`, `author::tab_chip`). They exist because
there was no preset to wear.

**The element library is half-built.** `crates/slides/src/elements/` holds
`badge · bar · divider · eyebrow · media · stat` — six elements on four
shelves, with a census, `ElementCategory`, `cost_tier` and a render gate. The
`Control` and `Container` shelves are declared and **empty**, documented as
arriving "by promotion / with recipes, later build-order steps."

**The ladder exists twice, in two vocabularies, with two registries.**

| | coarse | middle | fine |
|---|---|---|---|
| `LibSection` (Library route, 10 sections) | Templates | Blocks | Elements |
| `Shelf` (Author surface, 6 shelves) | Layouts | Combos | Pieces |

Same ladder. Two names, two censuses, two things to keep in sync.

**The overlay cannot reach the ladder.** `shelf_picker` is called from
`content()` (the Author *surface*) at `author.rs:1425`. `editor_modal()` begins
at 1651 and never calls it — grepping the overlay body for `shelf_picker` or
`Shelf::` returns nothing. Selecting happens *before* the overlay and outside
it; inside, there are only property tabs. **The flow is inverted.**

**Preview and save are real.** The live pane renders the open card and edits
autosave ("Everything you type here saves itself").

## Milestones

### P1 — The preset layer (semantic treatments)

**Scope:** `tokens/treatments.json` authored + generated exactly as
`traits.json` is, per §2b's schema: `{id, kind:"semantic", base, stack, tone,
on:{hover, press}}`. A resolver that turns a semantic id + state into a
`ResolvedStyle`, with per-state groups rather than a filter applied after the
fact. `TraitState` gains `Disabled` — today it is `Idle | Hover | Active`, and
a disabled control cannot be expressed at all.
**Law it installs (§2b):** authored surfaces name **intent** (`primary`,
`danger`, `ghost`, `surface`); only the design system binds intent to a
composite. Re-point one binding, every element wearing it moves.
**Deliverables:** the token file; build.rs generation (unknown ref fails the
build, as today); the resolver; `Disabled`; unit tests that a semantic resolves
to the same `ResolvedStyle` as its composite spelled out longhand.
**Not gated by the MOCK GATE** — this changes no pixels.
**Evidence gate:** `cargo green`; a test per state; generation drift test.

### P2 — The manifest (the availability contract)

**Scope:** a generated manifest enumerating what exists — presets, traits,
hues, states, elements, templates — that **both** the Library and the overlay
read. Nothing may offer a look absent from it.
**Deliverables:** the generated artifact + the census test that fails on drift;
one accessor both readers use; the honest-empty path for a shelf whose entries
are zero (the pattern already used three times in this lane).
**Not gated by the MOCK GATE** — data, not paint.
**Evidence gate:** a test that offering an unlisted preset is impossible;
census drift fails the gate.

### P3 — One vocabulary, one registry

**Scope:** `LibSection` and `Shelf` collapse to ONE registry with one set of
operator words. Machine ids stay stable where proof scripts and pilot keys
depend on them (`--lib-section`, pilot node keys) — renaming those breaks
recorded runs, so the id and the label move independently.
**Deliverables:** the single registry; both surfaces read it; `--lib-section`
census (flags ⇔ CLAUDE.md) still passes; the harness-flag audit updated in the
same commit if any id moves.
**Evidence gate:** one census function, one drift test; no second enumeration
anywhere.

### P4 — The Control shelf earns its first elements

**Scope:** `button` (and `toggle` if it recurs) land on the `Control` shelf as
real elements per §1's contract — standalone, data-in/paint-out, **receiving** a
`ResolvedStyle` rather than hard-coding one. `controls.rs` is deleted, not
shimmed. The editor's `chip` (8 sites), `big_button` (1 site) and the `150×84`
look tile's literals go with it.
**Depends on:** P1 (there must be a preset to wear) and P2 (it must be
offerable).
**GATED by the MOCK GATE** — this is a visible styling pass, and
`docs-history-2026-10-12:docs/plans/poam-visual-experience.md` V4 already scopes it.
**Evidence gate:** `git grep 'fn chip\|fn big_button' crates/editor/` empty;
`controls::` gone; tap-min test at two window sizes; a **disabled control
reports no click**; proof shots 1280×800 and 1100×700.

### P5 — The ladder inside the overlay (the flow, corrected)

**Scope:** the Templates→Blocks→Elements ladder becomes reachable from the open
card. Select applies to the card, the live pane previews it, autosave keeps it.
This is the inversion fix and it is the actual product.
**Deliverables:** the ladder in `editor_modal`; apply-to-open-card; the live
pane already exists and is reused; honest-empty for shelves with nothing on
them.
**Depends on:** P2 (one contract to read), P3 (one vocabulary).
**Evidence gate:** a test that selecting from inside the overlay mutates the
open card's document and the change survives a reopen; proof shots at both
sizes showing select → preview in one overlay.

### P6 — The Library, expanded greatly

**Scope:** the Library route grows into the browsable wall the operator expects
— every preset, every element, every template, shelved and previewed, driven
entirely by P2's manifest.
**Depends on:** P1–P3, and honestly on P1's pool being large enough to be worth
browsing. Five looks is not a library.
**GATED by the MOCK GATE** for its treatment.
**Evidence gate:** every manifest entry is reachable and previewed; a gallery
test that an existing entry which never renders fails.

## Open decisions (operator)

1. **Which words survive** in P3 — `Templates/Blocks/Elements` or
   `Layouts/Combos/Pieces`. Both are already written; one has to go.
2. **How big P1's initial pool is.** The PORT generated 537 by crossing
   presets × states × composition. This can be generated the same way, or
   authored narrowly and grown. That choice decides whether P6 is worth doing
   soon or much later.
3. **The four rulings** on `visual-language-v3-mock.html` (liquid glass; rail
   lane A/B; the stale clay line; overlay regression first or folded into V4) —
   these unblock P4 and P6 and the whole V-program.

## Risks

- **P1 without P4 is invisible.** A preset layer nothing wears looks like no
  progress. Mitigation: P1's own tests are the evidence, and P3 runs beside it
  so two milestones close before anything is gated.
- **Two registries collapsing breaks recorded proof runs.** `--lib-section`
  ids and pilot node keys are contracts. Mitigation: labels move, machine ids
  do not, and the harness-flag census enforces it in the same commit.
- **The BIG-BANG temptation.** §6.3 ratified one concentrated migration, and
  P4 touches only two crates on purpose. The other four hand-painted controls
  are explicitly out until the catalog pass.
- **A "moved" control silently losing behaviour** — the exact failure that lost
  #130's editor interior to hand-salvage. Mitigation: every deletion happens in
  the same commit that rewires its callers, so a missed site is a compile error.
- **Proof was skipped once already.** #176 merged double-green with no shot of
  the surface it changed, and shipped a clipped overlay. Every milestone here
  names its shots as acceptance.
